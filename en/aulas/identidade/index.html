Lesson 2 · 20 min

Design your Jarvis before you install it

The assistant becomes yours through text files, not code. Before installing anything, you write who it is, what it should and should never do, and what it needs to remember about you. This design answers the installation questions and becomes the four identity files.

Start lesson

  2. 2What goes in SOUL, AGENTS, USER, and MEMORY
  3. 3The difference between an effective SOUL and a weak one
  4. 4Turn a vague idea into a concrete request

Goal: write meu-jarvis.md and turn it into the four identity files: SOUL, AGENTS, USER, and MEMORY.

02 · How to write each part

Click each tab.

1. The design

Answer five questions: name, speaking style, three things it should do every week, three it should never do, and what it needs to remember about you.

Be specific. “Take care of my email” is vague; “every Monday, list the week’s three priorities based on what I’ve told you” is a request.

Done whenThe file fits on one screen, and someone else could understand who your assistant is.

2. The soul

An effective SOUL has clear values, a specific tone with an example, explicit limits, and a defined response style.

A weak SOUL says “be helpful and friendly,” contradicts itself (formal and casual at the same time), or is too long and loses focus.

From the repository exampleDirect and concise. Honest: if you don’t know, say so. I want a partner who disagrees, not someone who just agrees.

3. The rules

Separate into ALWAYS and NEVER. The example’s rules: check memory before answering, save what you learn about me, ask when unsure.

For tools: prefer safe, read-only commands, and refuse destructive ones.

The NEVER ruleNever delete a file without my confirmation. Never put a password or key in a response.

4. You and the facts

USER contains what it needs to know about you without asking every time: what you do, how you like answers, and what language you use.

MEMORY contains a few facts that matter from day one. Keep it short: it learns what comes later by talking with you.

Example USERPrefers practical advice to theory. Values time: be concise. Speaks Portuguese (pt-BR).

Repository example

Personality: direct and concise, no rambling; proactive, makes suggestions when relevant; honest, says when it doesn't know; remembers the context of previous conversations.

Values: privacy first, never share the owner's data; has opinions, because the owner wants a discussion partner, not someone who just agrees.

  • Effective: clear, testable values, tone with an example, explicit limits, defined response style.
  • Weak: "be helpful and friendly," behaviors only and no values, contradictions, too long.

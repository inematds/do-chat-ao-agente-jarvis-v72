Lesson 4 · 20 min

Build without coding: you choose, the agent builds, the test confirms

You don't write code. You pick the ingredients on a page, like in a grocery store, export a list, and ask Claude Code or Codex to build it, following the INTELECTO build plan. Then you prove it with the tests and a conversation in the terminal, before connecting it to Telegram.

Start the lesson

In this lesson you will

  1. 1The grocery store and the meu-assistente.md briefing
  2. 2Why the list alone isn't enough: the build plan
  3. 3The build request in one sentence
  4. 4Prove it with the tests and the conversation in the terminal

Goal: generate the briefing at the grocery store, ask the coding agent to build it with tests, and prove the core with the tests and a conversation.

01 · The path in five steps

Click each block. The heavy lifting is the agent's.

Click each block in the diagram to see what it does.

Start small: a few ingredients, tests passing, then grow. You can go back to the grocery store and add more.

02 · Each step, with what to check

Tap each step.

1. Choose a few

For a first Jarvis, the installation video chose eight: personality file, Telegram bot, WhatsApp, memory with SQLite search, encrypted secrets vault, forbidden-commands list, scheduling, and skills.

You can start with fewer: personality, Telegram, memory, and vault.

Done whenThe cart has 4 to 8 items and you can say what each one is for.

2. Export and combine

Export as a briefing for Claude Code and download meu-assistente.md. Clone the INTELECTO repository and put the briefing inside the folder.

What the tests revealed: the list alone is not enough. What makes the build succeed is the pointer to doc/intelecto.md.

In the folderintelecto/ with doc/intelecto.md, reference-repos/ and your meu-assistente.md.

3. Ask with tests

First ask for the plan: the agent reads everything and returns files, order, and questions (Docker or direct install? OpenRouter or Ollama? which model?). Answer in Portuguese.

With the plan approved, ask for the build with tests. Approve each command it wants to run only when you understand what it is.

If it gets it wrongDescribe the problem in Portuguese and ask it to fix it. This cycle is normal and expected.

4. Prove it

Run the tests. Then chat in the terminal: "remember that my name is ...", and right after, "what is my name?".

The last line of the example shows the name saved in the database: proof that it is not hard-coded text, and that the memory and the loop work together.

Done whenAll tests pass and the name appears on the DB line.

03 · The commands and the request

Run in the terminal, in the projects folder.

Terminal · download INTELECTO
git clone https://github.com/inematds/intelecto.git
cd intelecto
# copy the meu-assistente.md that the mercearia downloaded into here
Request 1 · the plan first
Read meu-assistente.md and the plan in doc/intelecto.md. Before writing any code, give me the plan back: files, order, and the decisions that depend on me. Use my identity (SOUL, AGENTS, USER and MEMORY that are in workspace/).
Request 2 · build with tests
Plan approved. Build my assistant in Python, with tests, following the contracts in doc/intelecto.md. The Telegram bot answers only to my user. Secrets never in the code. When you finish, run the tests and show me the result.
Terminal · prove the repository example
cd exemplo-jarvis
python3 -m unittest discover -s . -p 'test_*.py' -v
python3 smoke.py
Example from the repository
USER : lembre que meu nome é Nei
JARVIS: Seu nome é Nei.
USER : qual meu nome?
JARVIS: Seu nome é Nei.
DB   : ['Meu nome é Nei']

The DB line proves the name was saved in SQLite, not pulled from fixed text.

  • Memory: save → search → forget.
  • One full round of the loop: the test model asks for a tool, the loop runs it and replies.
  • The blocklist stops the dangerous command and lets the safe one through.
  • Settings go out and come back without losing anything.
  • The context contains the SOUL and the USER.

Exercise E3 of sequence 2, on the path the repository actually uses.

E3b · Your briefing

15 min

In the mercearia, check 4 to 8 ingredients and export meu-assistente.md to the INTELECTO folder.

Done when: the file is in the folder and each ingredient has its reason noted in your meu-jarvis.md.

E3c · Your built Jarvis

1 h

Copy your workspace/ folder from lesson 2 into the project, make requests 1 and 2, and follow the agent.

Done when: the tests pass and, in the conversation in the terminal, it answers with the name and the style you defined.

In the original exercise the step is ./start.sh. In today's repository the path is this: briefing + plan + agent builds. The setup assistant is one of the pieces the plan tells it to build.

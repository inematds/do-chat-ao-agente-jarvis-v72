Lesson 4 · 20 min

Build without coding: you choose, the agent builds, the test confirms

You don't write code. You choose the ingredients on a page, like at a grocery store, export a list, and ask Claude Code or Codex to build it by following the INTELECTO construction plan. Then you check it with tests and a conversation in the terminal, before connecting it to Telegram.

Start lesson

In this lesson, you will

  1. 1The grocery store and the meu-assistente.md brief
  2. 2Why the list alone isn’t enough: the build plan
  3. 3The one-sentence build request
  4. 4Prove it with tests and a conversation in the terminal

Goal: generate the brief at the grocery store, ask the coding agent to build it with tests, and check the core with tests and a conversation.

01 · The five-step path

Click each block. The agent does the heavy lifting.

Click each block in the diagram to see what it does.

Start small: a few ingredients, passing tests, then grow. You can go back to the grocery store and add more.

02 · Each step, and what to check

Click each step.

1. Choose a few

For a first Jarvis, the installation video chose eight: personality file, Telegram bot, WhatsApp, memory with SQLite search, encrypted secrets vault, list of forbidden commands, scheduling, and skills.

You can start with less: personality, Telegram, memory, and vault.

Done whenYour cart has 4 to 8 items, and you can explain what each one does.

2. Export and bring together

Export the brief for Claude Code and download meu-assistente.md. Clone the INTELECTO repository and put the brief inside the folder.

What the tests revealed: the list alone isn’t enough. What makes the build work is the pointer to doc/intelecto.md.

In the folderintelecto/ with doc/intelecto.md, reference-repos/, and your meu-assistente.md.

3. Ask for tests

First ask for the plan: the agent reads everything and returns the files, order, and questions (Docker or direct install? OpenRouter or Ollama? Which model?). Reply in Portuguese.

Once you approve the plan, ask it to build with tests. Approve each command it wants to run only when you understand what it does.

If it makes a mistakeDescribe the problem in Portuguese and ask it to fix it. This cycle is normal and expected.

4. Prove it

Run the tests. Then chat in the terminal: "remember my name is ...", followed by "what's my name?".

The last line of the example shows the name saved in the database: proof that it isn't fixed text, and that memory and the loop work together.

Done whenAll tests pass, and the name appears on the DB line.

03 · The commands and the request

Run these in the terminal, from your projects folder.

Terminal · download INTELECTO
git clone https://github.com/inematds/intelecto.git
cd intelecto
# copy here the meu-assistente.md that the grocery store downloaded
Request 1 · the plan first
Read meu-assistente.md and the plan in doc/intelecto.md. Before writing code, give me the plan: files, order, and decisions that depend on me. Use my identity (SOUL, AGENTS, USER, and MEMORY in workspace/).
Request 2 · build with tests
Plan approved. Build my assistant in Python, with tests, following the contracts in doc/intelecto.md. The Telegram bot replies only to my user. Never put secrets in the code. When you're done, run the tests and show me the results.
Terminal · prove the repository example
cd exemplo-jarvis
python3 -m unittest discover -s . -p 'test_*.py' -v
python3 smoke.py
Repository example
USER : remember my name is Nei
JARVIS: Your name is Nei.
USER : what's my name?
JARVIS: Your name is Nei.
DB   : ['Meu nome é Nei']

The DB line proves that the name was saved in SQLite; it didn't come from fixed text.

  • Memory: save → search → forget.
  • A full loop round: the test model requests a tool, and the loop runs it and responds.
  • The blocklist blocks the dangerous command and allows the safe one.
  • Settings can be saved and loaded without losing anything.
  • The context includes SOUL and USER.

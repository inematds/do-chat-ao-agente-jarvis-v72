Clase 3 · 15 min

La puerta: el bot en Telegram, con un solo dueño

Telegram es la puerta más simple: creas el bot en dos minutos y recibes un token. Ese token es la llave de la puerta. Quien tiene el token controla el bot, y cualquier persona puede mandarle un mensaje a un bot. Por eso la clase es mitad crear y mitad proteger.

Empezar la clase

En esta clase vas a

  1. 1Crear el bot con /newbot en @BotFather
  2. 2Por qué el token queda solo en el .env y fuera de Git
  3. 3Cómo el canal conversa con Telegram (long-polling)
  4. 4Por qué el bot necesita aceptar solo al dueño

Objetivo: crear el bot en @BotFather, guardar el token solo en el .env y definir que el asistente responda solo a ti.

02 · Crear y proteger, paso a paso

Haz clic en cada etapa.

1. Crear el bot

En Telegram, busca a @BotFather (el oficial, con sello de verificado) y envía /newbot.

Elige el nombre que aparece en la conversación y el @usuario, que debe terminar en bot. Él te responde con el token.

NombreUsa el nombre de tu meu-jarvis.md. El @usuario puede ser el nombre + _bot.

2. Guardar el token

Pega el token en una línea del .env de la carpeta del proyecto, como aprendiste en el nivel 1.

Verifica que el .env esté en el .gitignore. Los robots encuentran en poco tiempo una clave expuesta en GitHub.

Regla del nivel 1El token no aparece en ningún archivo además del .env.

3. Un solo dueño

Cuando vayas a construir (clase 4), pídele al agente que el bot responda solo a tu usuario de Telegram e ignore a los demás.

En la bóveda (clase 7) verás por qué esto importa todavía más cuando el asistente ejecuta comandos.

Pedido al agenteEl bot responde solo a mi usuario de Telegram; los mensajes de otras personas se ignoran y se registran.

4. Si el token se filtra

Un token en una captura, en un grupo o en un commit es un token filtrado. No lo borres y esperes lo mejor: genera uno nuevo en @BotFather y cámbialo en el .env.

El token anterior deja de valer, y quien lo tomó pierde el acceso.

En @BotFather/mybots → elige el bot → API Token → generar uno nuevo.

03 · El .env y la verificación

Cambia el texto entre < > por tu token. Nunca pegues el token aquí en el curso ni en un chat.

.env (en la carpeta del proyecto)
TELEGRAM_BOT_TOKEN=<pega aquí el token de @BotFather>
Terminal · verificar que el .env no se sube
grep -n ".env" .gitignore
git status --short
Terminal · buscar el token fuera del .env
grep -rn "<los 6 primeros caracteres del token>" . --exclude=.env
Simulación: ejemplo ilustrativo

grep muestra la línea .env en el .gitignore.

git status no lista el .env.

La búsqueda por el comienzo del token no encuentra nada fuera del .env.

Si git status muestra ?? .env, falta la línea en el .gitignore: agrégala antes de cualquier commit.

Si la búsqueda encuentra el token en otro archivo, bórralo de ahí y genera un token nuevo en @BotFather.

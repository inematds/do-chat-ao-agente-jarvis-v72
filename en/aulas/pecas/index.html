Lesson 1 · 15 min

The seven pieces of a Jarvis

Every agent, from the simplest to the most expensive, has the same seven pieces: a door, a heart, an identity, a brain, a memory, hands, and a vault. If you know the pieces, you choose better, spend less, and don't get locked into one product. INTELECTO is our example: small on purpose, so you can read it.

Start the lesson

In this lesson you will

  1. 1The path of a message, from Telegram to the model and back
  2. 2What each of the seven pieces does
  3. 3Why the loop with a brake sets an agent apart from a chatbot
  4. 4How contracts let you swap one piece without touching the rest

Goal: explain the path of a message and say, for each of the seven pieces, what it does and where it sits in INTELECTO.

  1. 1/8

    Channel

    This is where you talk to it. In INTELECTO, that's Telegram: one token and you're set, with no public address on the internet. The agent asks Telegram whether a new message has arrived, splits replies longer than 4,000 characters, and shows "typing" while it thinks.

  2. 2/8

    Loop

    It receives the message, thinks, uses a tool if it needs to, looks at the result, and thinks again, until it answers with text. It has a brake: at most five tool rounds per message. Past that, it has to answer.

  3. 3/8

    Identity

    Four simple files in the workspace folder: the soul, the rules, your profile, and the starting facts. With every message, the agent reads all four. Change the text, change the assistant, no programming.

  4. 4/8

    Brain

    The AI model. In the cloud, OpenRouter: one key gives you access to more than a hundred models. On your own computer, Ollama: no cost per message and nothing sent outside.

  5. 5/8

    Memory

    It stores what matters in a SQLite database on your machine, with word search and no API cost. With every message, it looks up what's relevant and puts it in the context.

  6. 6/8

    Tools

    Without tools it only talks; with them it gets things done. At the core: read and write files, list a folder, run commands, save to and search memory. Each tool describes itself, and the model reads that description to decide whether to use it.

  7. 7/8

    Vault

    API keys that are encrypted and tied to the machine, a list of forbidden commands, a 60-second time limit per command, and an audit log of everything it ran.

  8. 8/8

    The whole path

    You write on Telegram. The loop gathers identity and memory, sends them to the model, runs the tool it asks for, within the vault's limits, and the reply comes back through the same channel.

The same seven pieces show up in INTELECTO, in OpenClaw, in Hermes, or in a Jarvis you build yourself.

02 · Three ideas that hold the pieces together

Click each tab.

1. One owner only

INTELECTO is a personal assistant for one owner. It is not multi-user, doesn't depend on the cloud, doesn't need Docker, has no web dashboard, and isn't a black box.

The plan calls for about three thousand lines and seven dependencies: you can read it all.

Black-box testCan I explain what happens between my message and the reply? If not, it's a black box.

2. Loop with a brake

A chatbot answers and forgets. An agent thinks, acts with a tool, looks at the result, and thinks again.

With no ceiling, an agent can keep spinning and spending without finishing. That's why the five-round brake.

Loop ruleAt most 5 tool rounds per message; after that, reply with text.

3. Contracts

Each piece is defined by a contract: the channel has start, send, and stop; the provider receives the conversation and the tools and returns the response.

Want WhatsApp instead of Telegram, or Ollama instead of OpenRouter? It's another file with the same contract.

In practiceNew tool = new file in the same pattern. The registry finds it on its own, with no changes to the core.

4. Start small

The features guide organizes everything into eight corridors: identity, security, channels, memory, automation, integrations, skills, and architecture.

You don't need everything. Scheduling and web search, for example, are in the plan for the next phase.

Minimal setupLoop + a brain + a channel + a basic SOUL. Memory comes right after.

Example from the repository
  1. You write on Telegram.
  2. The channel receives it and hands it to the loop.
  3. The loop builds the context: SOUL + AGENTS + USER and the relevant memories.
  4. The model answers or asks for a tool; the loop runs it and returns the result (up to 5 rounds).
  5. The answer goes back through the channel.

Chatbot: answers, forgets when the conversation ends, has no identity, takes no action, doesn't know you.

Jarvis: remembers past conversations, has a written name and values, uses tools, and knows your context.

Lesson 1 · 15 min

The seven parts of a Jarvis

Every agent, from the simplest to the most expensive, has the same seven parts: a door, a heart, an identity, a brain, a memory, hands, and a vault. Knowing these parts helps you choose better, spend less, and avoid getting locked into one product. INTELECTO is our example: small on purpose, so you can read through it.

  1. 1/8

    Channel

    This is where you talk to it. In INTELECTO, that’s Telegram: one token and you’re ready, with no public internet address. The agent checks Telegram for new messages, splits replies longer than 4,000 characters, and shows “typing” while it thinks.

  2. 2/8

    Loop

    It receives your message, thinks, uses a tool if needed, checks the result, and thinks again until it replies with text. It has a brake: at most five tool rounds per message. After that, it has to reply.

  3. 3/8

    Identity

    Four simple files in the workspace folder: its soul, the rules, your profile, and the initial facts. The agent reads all four with every message. Change the text, change the assistant, without programming.

  4. 4/8

    Brain

    The AI model. In the cloud, OpenRouter: one key gives you access to more than a hundred models. On your computer, Ollama: no cost per message and nothing is sent outside your computer.

  5. 5/8

    Memory

    It saves what matters in a SQLite database on your machine, with keyword search and no API cost. With each message, it finds what’s relevant and adds it to the context.

  6. 6/8

    Tools

    Without tools, it only chats; with them, it gets things done. The core tools: read and write files, list folders, run commands, save to memory, and search memory. Each tool describes itself, and the model reads that description to decide whether to use it.

  7. 7/8

    Vault

    API keys encrypted and tied to the machine, a list of blocked commands, a 60-second timeout per command, and an audit log of everything it runs.

  8. 8/8

    The whole path

    You write in Telegram. The loop brings together identity and memory, sends them to the model, runs the tool it requests within the vault’s limits, and sends the reply back through the same channel.

The same seven pieces appear in INTELECTO, OpenClaw, Hermes, or a Jarvis you build yourself.

02 · Three ideas that hold the pieces together

Click each tab.

1. One owner

INTELECTO is a personal assistant for one owner. It isn’t multiuser, doesn’t depend on the cloud, doesn’t need Docker, has no web dashboard, and isn’t a black box.

The plan calls for about three thousand lines and seven dependencies: you can read it.

The black box testCan I explain what happens between my message and the response? If not, it’s a black box.

2. Loop with a brake

A chatbot responds and forgets. An agent thinks, acts with a tool, looks at the result, and thinks again.

Without a limit, an agent can keep spinning and spending without finishing. That’s why there’s a five-round brake.

Loop ruleAt most 5 tool rounds per message; after that, respond with text.

3. Contracts

Each part is defined by a contract: the channel has start, send, and stop; the provider receives the conversation and tools, then returns a response.

Want WhatsApp instead of Telegram, or Ollama instead of OpenRouter? Use a different file with the same contract.

In practiceNew tool = new file using the same pattern. The registry finds it automatically, without changing the core.

4. Start small

The feature guide organizes everything into eight areas: identity, security, channels, memory, automation, integrations, skills, and architecture.

You don’t need everything. Scheduling and web search, for example, are in the plan for the next phase.

Minimum setupLoop + one brain + one channel + a basic SOUL. Memory comes right after.

Repository example
  1. You write in Telegram.
  2. The channel receives it and passes it to the loop.
  3. The loop builds the context: SOUL + AGENTS + USER and relevant memories.
  4. The model responds or requests a tool; the loop runs it and returns the result (up to 5 rounds).
  5. The response goes back through the channel.

Chatbot: responds, forgets when the conversation ends, has no identity, doesn’t act, and doesn’t know you.

Jarvis: remembers past conversations, has a name and written values, uses tools, and knows your context.

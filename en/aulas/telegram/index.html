Lesson 3 · 15 min

The gate: the Telegram bot, with one owner

Telegram is the simplest gate: you create the bot in two minutes and get a token. That token is the key to the gate. Whoever has the token controls the bot, and anyone can message a bot. That's why this lesson is half creation and half protection.

Start lesson

In this lesson, you will

  1. 1Create the bot with /newbot in @BotFather
  2. 2Why the token stays only in .env and out of Git
  3. 3How the channel talks to Telegram (long polling)
  4. 4Why the bot should accept messages only from its owner

Goal: create the bot with @BotFather, store the token only in .env, and set the assistant to respond only to you.

INTELECTO was designed for one user. A Jarvis with access to your machine is powerful, and that’s exactly why it deserves care.

02 · Create and protect it, step by step

Click each step.

1. Create the bot

On Telegram, search for @BotFather (the official one, with a verified badge) and send /newbot.

Choose the name shown in the conversation and the @username, which must end in bot. It will reply with the token.

NameUse the name from your meu-jarvis.md. The @username can be the name + _bot.

2. Save the token

Paste the token on a line in the project folder’s .env, as you learned in step 1.

Check that .env is in .gitignore. Bots find exposed keys on GitHub quickly.

Step 1 ruleThe token doesn’t appear in any file other than .env.

3. One owner

When you build it (lesson 4), ask the agent to have the bot reply only to your Telegram user and ignore everyone else.

In the vault (lesson 7), you’ll see why this matters even more when the assistant runs commands.

Request for the agentThe bot replies only to my Telegram user; messages from other people are ignored and logged.

4. If the token leaks

A token in a screenshot, group, or commit has leaked. Don’t delete it and hope for the best: generate a new one in @BotFather and replace it in .env.

The old token stops working, and whoever got it loses access.

In @BotFather/mybots → choose the bot → API Token → generate a new one.

03 · The .env and the check

Replace the text between < > with your token. Never paste the token here in the course or in a chat.

.env (in the project folder)
TELEGRAM_BOT_TOKEN=<paste the token from @BotFather here>
Terminal · check that .env does not get pushed
grep -n ".env" .gitignore
git status --short
Terminal · look for the token outside .env
grep -rn "<the first 6 characters of the token>" . --exclude=.env
Simulation: illustrative example

grep shows the .env line in .gitignore.

git status does not list .env.

The search for the start of the token finds nothing outside .env.

If git status shows ?? .env, the line is missing from .gitignore: add it before any commit.

If the search finds the token in another file, delete it there and generate a new token in @BotFather.
